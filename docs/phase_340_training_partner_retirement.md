# Phase 340：退役虚构训练伙伴并保留真实快照边界

日期：2026-07-25

## 问题与参考结论

旧流程允许玩家在队伍面板凭空创建最多 4 名“陪练人物”，每人又凭空带
一只宠物。它们会进入本地和服务端战斗快照、获得经验，还被新手任务当作
正常组队条件。这与已确认的产品方向冲突：正式队友必须是真人玩家；未来
若确实需要临时伙伴，也只能克隆有来源、可过期的真实人物+宠物快照。

本地 StoneAge 参考的 `gmsv/src/char/char_party.c` 先筛选
`CHAR_TYPEPLAYER`，再把实际在线角色 index 写入队伍数组；队伍上限也是
5 名真实角色。参考流程中没有“玩家点击按钮后由服务器伪造人物与宠物”
这一组队兜底。Beastbound 因而回到成熟的真人组队心智，同时保留自己的
单人 PvE 可进入规则。

收益是正常界面、任务、战斗和奖励不再把假角色伪装成其他玩家，也不会
凭空创造宠物资产。代价是离线玩家不能再用四个假队友瞬间填满阵容；本期
用可直接开战的单人 PvE 和既有真人组队承接，不额外设计佣兵系统。

## 当前运行合同

### 玩家与 GM 界面

- 队伍面板只显示小队状态、邀请/离队和同图真人玩家。
- “陪练伙伴”页签、数量按钮、独立面板和 GM 菜单入口全部移除。
- 旧 `--training-partner-demo` 只作为开发兼容入口，打开真人队伍面板并
  明确说明该功能已退役。
- GM/QA 精确授权目录由 `local_qa_full_v3 / 31` 项升级为
  `local_qa_full_v4 / 30` 项；旧 `open_partner` 不再是授权命令。

### 单人、真人组队与 10V10

- 单人战斗仍由当前人物和其真实出战宠组成，不要求假队友。
- 真人组队继续读取每名在线队员的服务端 `teamSnapshot`，加入真人物和
  其出战宠；4 名真人队友加自己及出战宠可组成 10 个友方单位。
- GM 随机 10V10 观战实验室仍是独立开发工具，不依赖普通玩家档案中的
  `trainingPartners`。
- 危险草丛任务由聊天教学直接衔接，允许单人胜利完成；已退役的旧任务
  ID 仍可读取，但不会再次发放或卡住旧档。

### 服务端权威与旧档

- 新战斗快照始终产生空的 `trainingPartners`；队伍人数只统计真人账号。
- 旧 `training_partner_set_count` action ID 暂时保留，以便旧客户端得到
  明确的 `training_partners_retired`，但它不修改档案、不推进任务。
- 公共档案投影始终隐藏 `trainingPartners`。旧数据库行仍原样保留在私有
  档案中，不在本期做破坏性删除或 MySQL 迁移。
- 若旧档的当前任务正好是已退役教学，公共读取会投影到下一项有效任务，
  但不会为了读取偷偷改写其持久化内容。
- 旧战斗奖励/回放字段和档案迁移识别器暂留为只读兼容；当前房间创建边界
  已保证它们不可达，不能据此再次生成角色、宠物或经验。

## 未来真实快照伙伴合同

本期没有实现佣兵或离线伙伴。以后若重新立项，至少必须先定义并由服务端
签发以下事实，任何缺项都不得用默认人物或默认宠物补造：

| 范畴 | 必需事实 |
|---|---|
| 来源 | `sourceAccountId`、`sourcePlayerId`、来源档案 revision |
| 时效 | `capturedAt`、`expiresAt`、失效原因 |
| 人物 | 公开名称、等级、当前/最大生命、攻防敏、装备/精灵的战斗投影 |
| 宠物 | 真实 instance/form/species ID、等级、生命、攻防敏、当前主动/被动技能 |
| 所有权 | 快照只可用于一次或有限期 PvE 战斗，不复制背包、货币、宠物所有权或成长收益 |
| 竞技 | PvP、家族战、排行榜和交易相关战斗默认禁用 |
| 结算 | 奖励只归当前真实参与账号；快照来源账号和克隆对象均不获得资产或经验 |
| 验证 | 服务端签名/版本、来源可追溯、过期失败关闭、客户端不能覆盖任何战斗事实 |

## 旧引用审计

- 运行时创建器、默认名字/宠物生成器、面板构造和服务端快照转换器已删除。
- `trainingPartners` 数据键、迁移模块和禁用任务模板仅用于非破坏性旧档
  读取；普通公共投影与战斗均为零。
- 数值实验里的多队员已改称“模拟队员”，不再冒充正式玩家伙伴。
- 宠物模板里“转生仪式辅助宠”的概念属于 MM 转生材料，不是队伍伙伴，
  本期没有改变该宠物玩法或美术。
- `BattleModel.create_training_partner_battle` 的历史名字描述的是本地怪物
  战斗夹具；它不再创建友方伙伴。为避免把本期扩大成无行为收益的全局
  重命名，保留该内部 API，所有调用结果都经过无虚构友方断言。
