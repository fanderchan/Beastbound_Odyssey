# Phase 363：三宠融合权威规则、原子事务与安全关闭态

日期：2026-07-26

## 结论

P1.4 已完成第一段可独立验收的权威基础层，但尚未开放任何正式融合路线。

本阶段把项目所有者已经确认的融合规则写成共享严格目录、服务端随机权威、只读报价、三宠原子消耗、新宠生成、终局保护、公开投影、战斗被动解释和客户端关闭态合同。生产 `pet_fusion_recipes_v1` 当前保持 `runtimeEnabled=false`，基因档与配方均为空；没有正式融合形态、美术或玩家入口时，真实账号只能收到“尚未开放”，不会消耗宠物。

## 已锁定的产品规则

| 主题 | 现行合同 |
| --- | --- |
| 材料数量 | 恰好三只不同宠物：核心、共鸣一、共鸣二 |
| 材料阶段 | 都必须是资料完整的 `authority-v1` 普通宠，恰好一转，当前 Lv131–140 |
| 终局排除 | 0转、普通二转、进化、既有融合宠和转生MM均不能作为材料 |
| 外观与成长档 | 只由“核心族 + 共鸣一族”命中唯一配方；共鸣二不能改变目标形态或成长档 |
| 数值 | 成品只按目标融合形态配置独立生成，不读取三只材料的4V、隐藏成长、培养加成、等级数值、分位、评级或战力 |
| 初始主动 | `攻击 + 防御` 必定出现 |
| 特殊主动遗传 | 三只材料各自的显式血脉特殊主动独立进行一次50%判定 |
| 普通/训练主动 | 完全不遗传；当前技能栏里学过多少普通技能都不参与 |
| 已遗忘特殊主动 | 仍按形态的显式血脉基因参与50%，不从当前技能栏反推 |
| 主动重复 | 三次仍独立判定，成功后按技能ID去重，不补抽、不升级 |
| 被动遗传 | 恰好一个；核心40%、共鸣一30%、共鸣二30%抽取来源 |
| 成品阶段 | 新实例、Lv1、一转次数语义，立即进入“2转/进化/融合”不可逆终局 |
| 后续路线 | 不能付费重置、普通二转、进化或再次融合 |
| 骑乘 | 首版融合宠显式不可骑乘 |

三个特殊主动全部遗传的理论概率为：

`0.5 × 0.5 × 0.5 = 0.125 = 12.5%`

这个概率来自三次独立判定，不是额外配置的一次“全中”抽签。

## 显式血脉基因而不是技能栏推断

共享目录为每个未来获准参与融合的普通形态显式登记：

- 基因档ID；
- 族ID；
- 形态ID与对应 `authority-v1` 成长档；
- 唯一特殊主动；
- 唯一被动。

特殊主动必须存在于宠物战斗动作目录，并且不能出现在普通训练师技能目录；被动必须存在于服务端解释的被动目录。融合时只读这份显式基因档，不读取材料宠当前的 `activeSkillIds`、七格装备顺序、已学普通技能、旧遗传记录或遗忘记录来猜血脉。因此材料宠即使已经遗忘本族特殊主动，仍然保留该特殊主动的遗传机会；后来学会别族普通技能也不会篡改自身血脉。

目录还要求同一个“核心族 + 共鸣一族”组合在全目录中只能指向一个目标。共鸣二允许从明确批准的普通血脉集合中选择，但只提供第三组主动/被动候选，不能偷偷改变外观、元素、目标成长档或成品数值。

## 服务端随机与结果生成

每次确认融合只从服务端 CSPRNG 取得一个32字节根随机身份，再用独立命名域派生：

- 核心特殊主动判定；
- 共鸣一特殊主动判定；
- 共鸣二特殊主动判定；
- 被动来源判定；
- 成品自己的私有成长身份。

同一个私有根可以在服务器内部固定复现完整结果；不同标签不会共用一次顺序随机调用。成品成长身份与三个技能判定从同一权威根分域派生，但不会复用任何材料宠的私有 seed。

最终主动栏严格按以下顺序生成并填入七格：

1. `pet_attack`；
2. `pet_defend`；
3. 核心、共鸣一、共鸣二依次加入判定成功的特殊主动；
4. 对重复技能ID去重；
5. 剩余槽位留空。

被动栏只保存抽中的一个实例被动。战斗物化融合宠时只解释这个实例被动，不再把目标形态模板被动叠加进去；损坏的多被动资料失败关闭，不恢复模板被动作为补偿。

## 报价、确认与原子消耗

融合采用两段式服务端接口：

- `POST /pets/fusion/quote`：只读复核三只材料、配方、等级和候选基因，返回当前 profile revision、目录ID、公开概率与预期目标，不抽取结果、不消耗宠物；
- `POST /pets/fusion`：要求 operation ID、报价时的 profile revision 与目录ID，重新复核同一批材料后才打开随机上下文。

成功候选在同一个持久事务内完成：

1. 生成一个与三只材料都不同的新实例ID；
2. 按目标融合形态的独立成长档创建 Lv1 成品；
3. 写入一转次数语义、终局 lineage、公开遗传来源和私有随机审计；
4. 同时移除三只材料并加入一只成品；
5. 若被消耗材料包含当前出战宠，则把成品接替为当前出战宠；
6. 更新图鉴与 profile revision；
7. 持久 COMMIT 成功后才向玩家发布成功。

锁定、骑乘、离线挂机、战斗房间、收容待处理、档案 revision 过期、目录变化、目标配置损坏、随机权威异常或持久化失败，都会在发布前失败。确认回滚后仍是原三只宠；同一 operation ID 重放只返回第一次已提交结果，不会再次消耗或重新抽取。

素材校验不只看表面等级和 `growthModelVersion` 字符串：服务端会用正式成长周期重新 preflight 每只宠的完整 authority-v1 私有/公开状态，并复核严格的一转培养履历及血脉登记成长档。任何数值或成长快照篡改都会在抽随机、消费宠物和持久化之前失败。

历史档案只含旧 `profile.pets` 时，报价使用只读选择，不会为了兼容而改写冻结档案；执行时才在候选副本内一次性迁移为 `petInstances`，成功后删除旧容器。若新旧两个容器同时存在但内容不一致，报价和执行都失败关闭，避免出现“三只材料仍在旧容器、成品又写进新容器”的重复资产。

## 终局、公开资料与隐私

融合成品同时由两类证据识别为终局：

- 实例拥有 `fusionLineage`，即使其内部资料后来损坏；
- 当前形态命中融合目录登记的目标形态，即使 lineage 缺失。

所以融合宠无法借由删字段、损坏 lineage、GM 改价或旧档兼容路径重新获得付费重置或普通二转资格。

同样，进化目录登记的目标形态即使丢失 `evolutionLineage`，也不能作为融合材料；客户端与服务端还都会全局禁止任何融合目标重新登记为普通材料基因档，共鸣二通配符不能绕过这项终局互斥。

玩家公开资料只保留：

- 配方与目标形态；
- 三只已消耗材料的角色、实例、形态和名称；
- 判定成功的特殊主动及其来源角色；
- 唯一被动及其来源角色；
- 完成时间和终局阶段。

私有根随机、成长 seed、每次 roll、seed commitment、内部基因档ID和 durable operation 审计均不会进入公开 profile、HTTP 结果或日志文案。

## 客户端与生产关闭态

Godot 客户端读取与 Node 相同的 `pet_fusion_recipes.json`，并严格复核角色顺序、Lv131–140、攻击/防御保底、50%独立主动、40/30/30单被动、数值不继承、不可骑乘、目标终局重置策略和形态/成长档引用。该文件也进入共享数值摘要，客户端与服务器不能在不被发现的情况下使用不同融合概率。

客户端网络层具备只读报价和带 operation ID 的确认请求合同，但本阶段不新增玩家可见面板、GM正式入口或地图NPC。生产目录为空且关闭时，客户端明确处于不可用状态，不会用测试配方、占位外观或现有进化宠冒充融合成品。

## 本阶段明确不做

- 不擅自选择第一个核心族、同族路线或指定跨族路线；
- 不新增任何正式融合形态、元素、名称、成长数值或美术；
- 不开放融合宠骑乘；
- 不决定攻击/防御以后是否永久不可遗忘，也不决定成功遗传技能以后是否允许玩家主动永久遗忘；
- 不增加未经确认的融合石币、道具、税费、绑定或交易规则；
- 不迁移旧宠、不改 MySQL schema、不连接共享 MySQL、不修改真实玩家档案；
- 不制作截图或视频，因为当前没有可以诚实展示给玩家的正式融合外观和入口。

这些不是隐藏默认值：生产目录保持关闭，必须在项目所有者确认首条正式配方、基因档、成本/绑定政策、形态与美术后，才能进入下一段玩家可见开发。

## 验证

本阶段定向验收覆盖：

- 目录严格校验、测试配方隔离、资格边界、固定随机复现、重复主动去重、普通/训练主动排除和忘技不影响血脉候选；
- 12,000 组固定样本的主动50%、三主动全中12.5%、被动40/30/30分布；
- 三消一生、新实例、Lv1独立成长、绑定/出战接替、数值噪声隔离；
- HTTP 无副作用报价、revision/catalog 冲突、operation ID重放与私密随机零泄露；
- 持久 COMMIT 前不可见、row-local consistency scope 和确认回滚零变化；
- 融合终局的付费重置与普通二转拒绝；
- 融合实例被动不叠加模板被动；
- 生产空目录保持关闭，测试配方只能显式依赖注入。

最终结果：

- Node 融合、随机、目录、事务、HTTP、战斗、终局、付费重置、进化、公开投影与新宠工厂定向门禁：`125/125`；
- 12,000 组确定性分布样本：三个主动位置分别接近50%、三主动全中接近12.5%、被动来源接近40%/30%/30%，全部在固定容差内；
- Godot 独立 `pet_fusion_contract_check.gd`：PASS；
- Godot parse、共享目录、服务端协议、平衡版本回执、平衡摘要与战斗动作目录：`6/6`；
- Pet Design Inspector：`errors=0 warnings=0`；
- 当前 headless idle `process_total=0.15..0.63ms`；真实移动探针约60 FPS、`process_total=0.22..0.49ms/status=ok`；
- `git diff --check` 与相关 Node 语法检查：通过。

完整服务端套件也已执行，但当前仓库基线本身并非全绿；其中群弓十目标、骑宠提前倒地后的经验、毒杀骑宠经验三项在独立导出的干净 `HEAD d1aab6b42` 上可原样复现，因此不把它们伪报为本阶段通过，也不把无关战斗修复混入融合提交。本阶段验收以以上定向门禁为准。

## 路线图状态

P1.4 父项继续保持未完成。本阶段只完成“权威规则与原子事务基础”，下一段仍需要项目所有者先确认首个正式核心族、两条精选组合及对应特殊主动/被动基因档，再生产目标形态、美术、玩家确认界面和真实端到端验收。
