# Phase 368：宠物成长品质即时反馈与宠物页信息架构

## 结论

本阶段没有替换 Beastbound 现有成长、转生、进化或融合机制，也没有把 Lv1 四维并入成长品质。它只把已经存在的公开成长观察整理成玩家更容易感知的蓝／紫／橙／红／彩反馈，并按项目所有者选定的「觉醒式沉浸排版」方案 2 重排宠物页：

- 1280×720 宠物页改为全屏沉浸式木框和深色哑光舞台；
- 左侧显示当前宠物、512px 正式身份形象、等级、战力、状态、成长品质及阶段头像；
- 右侧用 `属性 / 成长 / 技能 / 培养` 四个纵向页签组织信息，图鉴回到左下独立入口；
- 成长页继续保留 `0转 / 1转 / 2转或进化或融合` 的既有履历；
- 底部改为横向宠物卡带，品质色装饰卡框，状态与完整信息通过详情和提示继续可见；筛选／排序默认收起，通过右侧“状态”按钮展开；
- Lv1 显示“成长未观察”，Lv2–19 显示实时颜色并标记“观察中”，Lv20 起正式定档；
- 只有 Lv20 起、已有至少 19 次升级证据，且某项公开实测均值超过当前形态／阶段公开上限时，才在该项显示“爆”。

玩家提供的《石器时代：觉醒》截图只用于确认审美差距与信息层级。最终视觉基准是本项目重新生成并由项目所有者选中的方案 2；本阶段没有复制参考游戏的美术资产、数值或名称。

## 已确认的品质合同

品质只读取公开成长分位，不读取或合并 Lv1 四维：

| 成长分位 | 内部档位 | 玩家颜色 | 玩家名称 |
| --- | --- | --- | --- |
| `0.0–24.9` | D | 蓝 | 普通 |
| `25.0–54.9` | C | 紫 | 优秀 |
| `55.0–84.9` | B | 橙 | 稀有 |
| `85.0–94.9` | A | 红 | 极品 |
| `95.0–100.0` | S | 彩 | 完美 |

共享配置位于 `client/godot/data/balance/pet_growth_quality_presentation.json`，客户端和服务端都从这份配置读取。配置严格校验五档顺序、分位门槛、颜色语义、Lv20/19 次升级成熟门槛及“爆”字比较方式；漂移时失败关闭。

`彩` 使用多段色带表达，但仍只有一个 S 档，不增加新的数值层级。

## “爆”字的真实含义

“爆”不是新成长公式，也不是伪造一次“某级随机暴涨”：

1. 只使用玩家已经看得到的当前四维、不可变 Lv1 四维、等级和公开成长档；
2. 以 `(当前值 - Lv1值) / 已升级次数` 得到公开实测均值；
3. 与当前形态／当前阶段的公开上限比较；
4. Lv20 前即使暂时超过上限也不显示“爆”，避免单级整数取整噪声制造误判；
5. Lv20 后只有真正超过上限的行显示“爆”，射中其他行不会连带亮起；
6. 进化前一转履历的上限由“历史物种上限 + 一转公开增量上限”组成，不能把正常一转收益误报成爆发。

现有连续成长内核本身没有新增逐级幸运骰。本阶段保留现有公式和历史宠价值，只把公开整数实绩可能略超公开连续基准的少量情况转成可见惊喜。

## UI 信息架构

### 左侧宠物展示

- 名称、形态、终局阶段、品质、等级、战力和状态集中在全高主舞台；
- 主舞台优先通过 `PetShowcaseArtCatalog` 加载全部 34 个形态既有的 512×512 正式三分之四身份图；缺图时才降级到现有 world/battle idle 目录；
- 展示纹理按真实非透明区域裁边后等比居中，不把 256px 动作图放大冒充高清源；
- `0转成长 / 1转成长 / 2转·进化·融合` 使用真实形态头像、木质圆环和金色选中环，并保留禁用与选中态；
- 未批准或尚未制作的形态显示“形象制作中”，不会借 QA overlay 绕过正式美术门禁；
- 只有面板可见时才运行有界 idle 定时器，关闭面板后停止。

### 右侧详情

- `属性` 保留原实例详情；
- `成长` 首屏显示品质徽标、成熟状态、公开上限、总成长和四项成长条；成长表格、双雷达、人工参考线、重置与进化信息仍由既有详情合同提供；
- `技能` 和 `培养` 继续打开既有权威面板，不新造第二套技能／培养状态；
- `图鉴` 保留原图鉴详情和点击合同，但视觉入口移到底栏左端；
- 页签改为纵向后，成长页隐藏与判断无关的次要管理操作，属性与图鉴仍保留原操作能力。

### 底部宠物栏

- 原左侧纵向清单改为横向滚动卡带，右端提供真实“前／后”翻页控件；
- 筛选、排序、排序方向、左键查看和右键驯宠合同均保留；
- 卡片首屏只显示正式静态宠物帧、品质边框和等级，名称与完整状态继续保留在提示及详情中，以免底栏重新变成文字表格；
- 排序或筛选后仍重新填充卡带；此次顺带修复了非默认排序下详情区和列表未刷新的旧控制流缺口。

### 原创视觉资产

- 运行资产位于 `client/godot/assets/ui/pet_management_awakened_v2/runtime/`；
- 可替换源图、生成提示、来源、所有权和哈希清单位于同目录的 `source/`、`source-and-ownership.md` 与 `asset-manifest.json`；
- 木质背景、纵向页签、通用按钮和宠物卡框来自已归档的原创 V1 资产；阶段环、顶栏爪印、帮助章、攻略挂签、图鉴盾牌、品质框、关闭、改名和翻页控制由本项目新生成；
- 六套派生／同步脚本与 `51` 个运行 PNG 的尺寸、色彩模式、SHA-256 已封口；其中正式宠物展示图 `34/34` 与各自身份源文件逐字节一致；
- 项目所有者于 2026-07-28 对该版实机排版明确回复“这版可以”；因此本 UI 资产包状态已从 `owner_review_pending` 冻结为 `approved`。该决定只覆盖当时展示的宠物页布局与 UI 资产，不自动批准随后新增的独立宠物大头照。

## 权威、隐私与兼容边界

- 服务端 `pet-observed-growth-screening` 在不改变原 `evaluatePet` 返回结构的前提下，新增纯展示方法；
- 展示方法只消费公开观察结果、公开物种范围和公开战力权重；
- private seed、private roll、逐级隐藏记录和最终隐藏品质均不进入返回值；
- 没有新增玩家写接口、货币规则、宠物 mutation、协议版本或 MySQL 迁移；
- 普通二转、进化、融合的终局互斥和付费重置禁用规则完全不变；
- 融合成长仍不继承材料宠数值，进化与普通二转仍沿用已确认的胚子关系。

## 性能与剩余边界

成长品质只在宠物面板刷新、选择宠物或切换阶段时计算；没有加入 `_process`、`_draw` 签名、世界 HUD 或网络轮询热路径。自定义成长条只在数据变化时重绘，底部卡片只取一张静态正式帧。

最终 60 FPS 定向实测中，idle `process_total=0.04–0.05ms`；真实跨帧移动 `=0.04–0.05ms` 且 `status=ok/path_len=11`；六宠成长页展开后稳定样本 `process_total=0.05ms`。当前不包含新的逐级随机成长机制、彩色全屏开奖动画、独立宠物大头照审批、融合入口开放或移动端专用布局。正式晶甲乌力身份图的真实三分之四姿势比概念绘姿略窄，这是保持正式源图不变形的 P3 差异，不阻断已经获得的 UI 审美验收；以后新增的大头照仍需单独留在 `owner_review_pending`，不能继承本阶段批准。
