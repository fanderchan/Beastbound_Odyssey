# Phase 370：宠物管理服务端权威与自动检查收口

日期：2026-07-29

## 结论

本阶段只收口已经确认存在的宠物管理安全缺口，不改变培养、放生、融合、骑乘或成长数值规则：

- `POST /profile/action` 现在必须携带合法 `Idempotency-Key`；
- 兽栏存取与批量存入由服务端核对远程兽栏能力或当前权威位置；
- 宠物技能学习／覆盖由服务端核对指定训练师与当前权威位置；
- 进化成功会在同一档案事务中永久登记目标形态为图鉴“已见／已捕获”；
- 四个已经漂移的 Godot 宠物检查改为验证现行 `authority-v1` 合同。

本阶段没有开放融合配方或玩家融合入口，也没有修改宠物培养、永久清理、地面丢宠、休息回血、状态循环、成长概率、技能遗传、美术或音频。

## 服务端权威合同

### 通用档案操作幂等

`/profile/action` 与付费重置、进化、融合等资产写接口使用相同的 HTTP 幂等门禁：

- 缺少或格式错误的操作键在进入档案写入前拒绝；
- 相同账号、相同键、相同意图只重放第一次持久化回执，不重复消耗或增加档案 revision；
- 相同账号、相同键、不同意图返回冲突，档案保持不变。

正式 Godot 客户端原本就会为档案操作生成操作键，因此该门禁不改变正常玩家交互，只关闭自定义请求省略操作键的旁路。

### 兽栏权限

`pet_stable_toggle` 与 `pet_batch_store` 只接受两种服务端可证明的访问方式：

1. 权威档案已经拥有 `remoteStable`；
2. 玩家已经停稳，且权威运行位置位于正式地图中 `stable` 服务 NPC 的八邻接格，Chebyshev 距离不大于 1。

客户端自报的 `openedFromStable` 等字段不参与判断。没有位置、仍在移动、错误地图、距离两格及以上、伪造面板来源都会在克隆和写入档案前拒绝；拒绝不改变宠物状态或档案 revision。地图点还必须是非空 ID、`kind=npc`、`actionType=stable` 的正式交互点，宽泛的设施标签不能单独授权。

### 宠技训练师权限

`pet_skill_set_slot` 必须携带明确 `trainerId`，且该 ID 必须同时满足：

- 当前权威地图中存在同 ID 的交互点；
- 交互点声明为宠技训练师；
- 玩家已经停稳，且权威位置位于该 NPC 的八邻接格；
- 交互点必须是 `kind=npc`、`actionType=pet_skill_trainer`，并且 `id` 与 `trainerId` 精确一致。

`remoteStable` 只豁免兽栏，不豁免训练师。仍在移动、错误训练师、错误地图、距离两格及以上或伪造 `openedFromTrainer` 均在扣石币和修改技能前拒绝。

### 进化图鉴

进化目标宠替换成功、费用应用成功后，服务端在持久化同一候选档案前调用统一图鉴记录器，将目标形态登记为“已见／已捕获”：

- COMMIT 前不会向运行内存发布；
- COMMIT 回滚不会留下图鉴记录；
- 同一操作键重放不会重复登记或增加 revision；
- 服务重启后记录仍从持久化档案恢复。

## 自动检查修正

本阶段只修测试夹具与断言，不为通过检查修改正式玩法：

- `--auto-pet-growth-check` 从旧 `growthRecord.finalStats` 改为核对现行 `authority-v1` 公开成长信封、四维、战力与战斗 Actor；
- `--auto-pet-individual-growth-check` 不再要求退役的 `individualSeed / individualVariance / growthRecord` 公开字段，改为验证同形态个体差异、公开权威标记与私有字段不泄露；
- `--auto-pet-cultivation-check` 将旧按钮文案“转强”对齐正式文案“培养”；
- `--auto-pet-growth-rule-preview-check` 使用隔离本地档案夹具并展开现行成长详情，不再用伪服务器会话触发无关 WebSocket 401。
- 共享 `server_pet_profile_public_v2` 向量同步现行绑定石币公开字段，并由 Node 精确 DTO 测试与 Godot 服务端宠物成长边界检查共同消费，防止双端各自只验证自己的静态夹具。
