# Phase 375：宠物技能页木框裁切修复与技能等级决策

## 已完成：技能卡越过木框

项目所有者在 Phase 374 录像的中段滚动状态发现，下一张技能卡的顶部描边越过了
技能面板的木框底边。

根因不是技能卡高度，而是详情滚动区原先只有 16px 底部边距：它的裁切矩形延伸
到木框外沿，动态绘制的技能卡会覆盖先绘制的木框。卡片自身的内容裁切不能阻止
整张卡覆盖父级背景；给列表尾部增加空白也不能修复中段滚动。

最小修复：

- 详情面板底部安全边距从 16px 调整为 32px；
- 显式设置技能详情 `ScrollContainer.clip_contents = true`；
- 自动检查同时断言裁切已开启、滚动视口与底部宠物栏之间至少保留 32px。

真实 `Main.tscn` 回归实测安全距离为 34px。

## 待确认：技能 Lv1–Lv5

当前权威运行时没有技能等级。主动、被动、七个技能槽、遗忘记录和融合基因都只
保存技能 ID；训练师也只有首次学习／覆盖，没有升级动作。Phase 374 不显示
“Lv1”是为了避免 UI 先伪造尚不存在的玩法。

建议新增三个正交层级：

1. 技能目录定义同一稳定技能 ID 的 Lv1–Lv5 完整数值曲线；
2. 宠物形态定义默认技能等级上限，以及少量按技能覆盖的上限；
3. 宠物实例保存该宠已经练出的 `skillLevels`。

“能不能学习”继续由既有学习资格控制；等级上限只限制能练到几级，不能自动授予
技能。普通宠可以只到 Lv3，招牌宠的一项核心技能可以到 Lv4／Lv5。客户端仍只
提交技能 ID，服务端从权威宠物实例解析等级和最终效果。

第一批建议：

- 当前固定技能数值作为 Lv1，旧宠缺少等级字段时按 Lv1 兼容，不降低现有战力；
- 普通训练主动技能开放 Lv1–Lv5；
- 基础攻击、防御显示“基础”，绝对免疫等二元规则被动显示“固有”，不伪造五级；
- 数值型被动的数据架构预留等级，但第一批不开放通用升级；
- 每级只增强一个主轴，例如伤害、命中率或治疗量，不能同时增长伤害、目标数和
  状态回合；
- Lv5 相对 Lv1 的总预算先控制在约 25%–35%，具体曲线必须经仿真后落表；
- 新增独立服务端权威动作 `pet_skill_upgrade`，不把升级混入学习、移槽或遗忘。

唯一会改变融合价值、且必须由项目所有者确认的规则：

> 技能被覆盖或遗忘后，已经练出的等级是否永久记在这只宠物身上；融合成功遗传
> 该特殊技能时，是否连原等级一起继承，并最终受融合成品的等级上限限制？

推荐：永久记忆；融合继承原等级，但不得超过成品上限。这与已经确定的“特殊主动
即使遗忘仍可遗传”一致，也不会吞掉玩家已经投入的技能培养资源。

在该规则确认前，不修改技能目录数值、训练价格、存档、融合或战斗结算。
