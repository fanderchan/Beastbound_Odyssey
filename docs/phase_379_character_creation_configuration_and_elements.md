# Phase 379：人物创建配置页与元素权威

## 产品结论

本阶段覆盖 Phase 378 中“空槽点击后直接弹出名字输入框”的旧入口。固定四槽和角色
资产隔离继续保留，但空槽现在必须进入完整人物创建配置页；第一版不制作多人营地群像
选择演出，直接实现项目所有者确认的第二阶段页面。

玩家流程固定为：

```text
登录 -> 角色槽 -> 点击空槽 -> 选择人物外观 -> 分配元素 -> 修改名字
     -> 确认创建 -> 返回角色槽 -> 选择角色进入游戏
```

返回创建页不得占用槽位。服务端只接受一次性原子创建请求，不能先创建无外观或无元素
的半成品角色。

## 首批人物外观

首批提供四个原创人物外观：

- `novice_hunter_v1`：见习猎人，现有持锤少年；
- `obsidian_scout_v1`：曜石斥候，黑发少年；
- `frost_whisper_v1`：霜语游侠，白发少女；
- `ember_spark_v1`：焰芽斗士，红发少女。

人物外观纯视觉，不改变初始四维、成长、职业、技能或元素。服务端只保存和校验
`appearanceId`，客户端依据共享目录加载独立头像、创建页全身展示、世界和战斗资产；
客户端不能提交任意资源路径。

正式人物不能只交付创建页头像。每个外观最终需要同一身份锁下的独立头像、透明全身
展示、世界真八向 `idle 1 + walk 4`，以及固定战场双视角的正式动作矩阵。主流程不得
把静态 NPC、其他人物动作或镜像素材冒充完成资产。

## 元素规则

人物拥有独立于四维加点的地、水、火、风元素：

```json
{
  "earth": 0,
  "water": 10,
  "fire": 0,
  "wind": 0
}
```

权威校验规则：

- 四项必须是 `0..10` 的整数；
- 总和必须正好为 `10`；
- 最多两种元素非零；
- 地与火不能同时非零；
- 水与风不能同时非零；
- 必须在创建成功前分完，不接受客户端预计算的克制结果。

人物元素立即进入现有元素克制体系，复用同一公式和标签，不另造人物专属倍率。外观
与元素完全解耦。

## 新账号与旧角色

新账号注册后拥有四个空槽、无 active 角色，必须先完成创建页。注册成功本身不再隐式
创建默认角色或默认档案。

旧角色保留原名、`playerId`、档案和资产：

- 缺少外观时只做兼容映射 `novice_hunter_v1`；
- 缺少人物元素时返回 `needsElementAllocation=true`，首次进入角色前打开同一配置页；
- 旧角色补配点时锁定人物和名字，只允许提交元素；
- 补配点免费且仅一次，服务端不得擅自分配默认元素；
- 未完成补配点的旧角色不能进入权威战斗。

今后的普通元素重置价格、次数和入口不在本阶段决定；不得把“首次兼容补配点”实现成
可重复免费重置。

## 权威接口

创建请求：

```text
POST /characters
Idempotency-Key: required

slotIndex?
displayName
appearanceId
elements: {earth, water, fire, wind}
```

旧角色一次性补配点：

```text
POST /characters/allocate-elements
Idempotency-Key: required

elements: {earth, water, fire, wind}
```

补配点端点只作用于当前服务端会话选中的角色。成功后返回更新后的角色摘要和 revision；
已有合法元素时再次调用必须拒绝。

## UI 合同

1280×720 PC 页面按项目所有者提供的参考图组织：

- 左上为返回；
- 左侧为四个独立圆形头像，可用左键切换；
- 中间显示当前人物的大尺寸全身展示；
- 右侧为地水火风四行减号、十格与加号；
- 元素区持续显示剩余点数和禁配原因；
- 下方为名字输入、随机名字按钮与“创建角色”；
- 无效配点、缺失正式资产、非法名字或请求中状态必须阻止提交；
- 玩家界面不显示 raw code、资源路径、schema、QA 或 agent 文案。

## 验证门禁

- 服务端覆盖注册零角色、四槽创建、非法外观、全部元素边界、幂等重放、旧角色一次性
  补配点和 MySQL profile 增量保存；
- Godot 覆盖四人物切换、配点约束、名字校验、返回不创建、缺失资产禁用、创建请求和
  旧角色补配点；
- 元素战斗测试证明人物和宠物复用同一克制规则；
- 实机用 `Main.tscn` 在 1280×720、1×速度录制完整流程；
- 参考图与实机同状态并排进入 `design-qa.md`，P0/P1/P2 清零后才能交付；
- 新人物正式美术保持 `owner_review_pending`，直到项目所有者观看视频并明确验收。

## 非目标

- 本阶段不制作多人营地群像、人物跳入和镜头拉近演出；
- 不开放付费扩槽、删除角色、角色换槽或账号间转移；
- 不决定创建后的普通元素重置费用；
- 不复制参考游戏的像素、角色设计、商标或原始美术资产；
- 不把创建页 UI 图片当作世界、战斗或骑乘人物资产。

## 实施结果（2026-08-01）

本阶段已按上述合同完成：

- 新账号由服务端建立四个空槽，不再隐式创建默认角色；创建请求把槽位、名字、外观和
  十点元素作为一个幂等原子操作提交；
- 旧角色缺外观时只兼容映射见习猎人，缺元素时只开放一次免费补配点；未补配点角色可
  继续查看队伍，但不能进入权威战斗；
- 人物元素进入服务端战斗 actor，并与宠物复用同一元素克制倍率和战斗事件反馈；
- 客户端完成四空槽、四外观切换、十点配点、禁配提示、随机名字、键盘改名、返回和创建
  回槽；全部主操作均可由左键和键盘完成；
- 四套原创人物均交付独立头像、全身展示、真八向世界动作 40 帧、双战斗视角十二动作
  180 帧；每套正式运行矩阵合计 220 张 `256×256 RGBA`，两视角均满足
  `down-8 == revive-1`，不使用运行时镜像；
- 四套素材已经接入运行时供实际流程验收，但主观美术结论仍保持
  `owner_review_pending`，直到项目所有者观看本阶段视频后明确接受。
