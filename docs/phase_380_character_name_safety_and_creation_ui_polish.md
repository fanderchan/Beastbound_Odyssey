# Phase 380：角色随机名安全与创建页细节修复

## 问题与产品结论

项目所有者在真实创建页录屏中确认了三个问题：

- “换一个”按钮被通用次级按钮的最小宽度撑开，越过右侧配置板边界；
- 按钮虽然会改名，但只是顺序轮换十个固定名字，没有真正的随机候选，也没有角色名
  内容安全策略；
- 地属性仍使用棕色，与项目约定的绿色元素语义不一致。

本阶段把三点作为同一创建页修复完成。随机名不是只在客户端做表面过滤：客户端负责
即时反馈和安全候选生成，服务端在创建角色前执行最终权威校验。

## 角色名策略

共享策略文件 `client/godot/data/character_name_policy.json` 固定以下合同：

- 使用经过人工筛选的前缀和后缀组合生成随机名字，首批可组合出至少 400 个候选；
- 每次点击尽量避开当前名字，生成结果仍必须通过同一安全检查；
- 拦截冒充官方／GM／客服、广告联系方式、明确低俗骚扰词和明确敏感仇恨词；
- 拦截超过策略上限的连续数字，降低手机号、QQ 号等联系方式进入角色名的风险；
- 扫描前统一大小写和全角／半角，并折叠空格、标点、符号、组合记号及不可见格式字符，
  防止使用“Ｇ · M”“微🌟信”“傻_逼”等形式绕过；
- 玩家只看到统一提示“这个名字不能使用，请换一个。”，界面和接口均不泄露命中的
  具体词条或内部分类。

策略以数据文件维护，但创建结果始终由服务端判定；修改客户端或直接调用接口不能绕过。
这不是自然语言语义审核，也不承诺穷举所有新型谐音。后续新增词条不需要改创建协议。

## UI 合同

- 名字输入框和“换一个”按钮必须完整位于 `CreationBoard` 内，彼此不重叠，并保留与
  面板左右一致的安全边距；
- 只为该短按钮覆盖通用按钮的最小宽度，不改变背包、宠物等页面的共用按钮尺寸；
- 地属性文字、已点亮格子和相关创建页反馈统一使用绿色；水、火、风沿用既有蓝、红、
  黄元素颜色；
- 敏感名字输入后即时显示通用玩家提示并禁止创建，安全随机名恢复正常创建状态；
- 主操作继续支持左键，随机按钮不得依赖右键或调试入口。

## 验证门禁

- Godot 模型检查覆盖普通名字、全角／分隔符／符号绕过、连续数字、随机候选和策略加载；
- 创建页流程检查读取控件实际尺寸，证明名字输入和随机按钮均被配置板包含且不重叠；
- 服务端单元测试覆盖策略 fail-closed、NFKC 规避、分类拦截、长数字、正常名字和创建失败
  不落档；
- 真实 `Main.tscn` 以 `1280×720 / 1×` 展示边界修复、绿色地元素、多次随机换名、非法名
  拦截和安全名恢复；
- 将项目所有者截图与同状态实机图放在一个比较输入中完成 Design QA，P0/P1/P2 清零后
  才能交付。

## 非目标

- 不引入外部第三方内容审核服务，也不上传玩家输入；
- 不在玩家界面显示词库分类、命中词、raw code 或 QA 文案；
- 不借本次修复更改角色名长度、角色槽、元素点数、禁配关系或人物外观；
- 不在本切片改写注册账号 `displayName` 或聊天／邮件的身份展示；这些历史账号级昵称
  仍需在后续跨域身份治理中改为当前角色身份并接入同类安全策略；
- 不全局缩小共用次级按钮，不修改其他已验收页面布局。

## 实施结果（2026-08-01）

- 创建页只为“换一个”按钮覆盖通用次级按钮的最小宽度：姓名输入为 `262×50`，按钮为
  `94×50`，两者间隔 10px，按钮右侧仍保留 42px 配置板内边距；
- 地属性文字和已点亮元素格统一使用绿色，水、火、风的既有颜色与元素规则均未改变；
- 共享名字策略提供 24 个前缀和 24 个后缀，共 576 种安全随机组合；连续点击会避开当前
  名字，生成结果继续经过同一策略校验；
- 客户端提供即时通用提示，服务端在创建角色前使用完整 NFKC 规整并权威拦截冒充、
  广告联系方式、低俗骚扰、敏感仇恨、不可见字符、纯符号及过长连续数字；拒绝请求不会
  建立角色或写入 profile；
- 短拉丁词使用边界语义识别，`真GM玩家`、`我是ADMIN本人`、`小王QQ客服` 会被拦截，
  `Sigma`、`Enigma`、`Badminton` 等正常英文不会因内部字母片段被误伤；
- 玩家端只显示“这个名字不能使用，请换一个。”，不会暴露命中词、分类或服务端内部码。

## 验证结果

- 服务端名字策略和角色创建权威测试 `16/16` 通过；两个相关 Node 源文件语法检查及共享
  JSON 解析检查通过；
- Godot 全项目 parse、角色创建模型、名册模型和真实 `1280×720` 创建页流程检查通过；
  自动检查读取控件实际矩形、地元素文字颜色和已点亮格样式，而不是只比对配置常量；
- 录屏工具 Python 测试 `4/4` 通过；最终 `Main.tscn` 视频为 `22.900s / 687` 帧、
  `1280×720 / 30 FPS / 1.00×`、H.264/AAC，完整音视频解码通过；
- 真实跨帧移动性能探针稳定 `60 FPS`，`process_total` 中位约 `0.33ms`、最高
  `0.47ms`；页面空闲按项目既有策略保持目标 `30 FPS`；
- 最终视频：
  `.run/evidence/phase380_character_name_safety_owner_review/phase380-character-name-safety-final-v1/character-name-safety-owner-review-1x.mp4`；
- 用户问题截图与同状态实机帧已合并成一个比较输入，`design-qa.md` 的 P0/P1/P2 均为
  0，结果为 `final result: passed`。

本阶段未运行完整本地 CI，也未连接共享 MySQL 或真实玩家后端；以上验证使用聚焦单元／
运行时检查、隔离录制与本地性能探针完成。注册账号级 `displayName` 的跨聊天／邮件身份
治理仍属于后续独立任务，不影响本次角色创建服务端权威校验。
