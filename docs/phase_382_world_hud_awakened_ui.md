# Phase 382：觉醒式世界主界面 HUD

## 结论与参考意图

项目所有者要求世界主界面继续采用其提供截图所代表的成熟产品信息层级：地图和常用入口
集中在画面上沿，角色与战宠、任务和队伍集中在右侧，聊天放在左下，核心菜单放在右下，
并允许把整套 HUD 收起后安静观战。

Beastbound 本阶段据此完成的是一套原创重制，而不是外部产品的像素级复刻：参考截图只用
于判断视觉层级、锚点关系、暗木暖金材质、入口密度和交互节奏；运行时代码、图标、人物、
宠物、地图、文案与数据均来自 Beastbound 自身。没有复制、裁切、描摹或嵌入参考游戏的
UI 贴图、角色、美术资产、商标、数字或红点状态。

本阶段以 PC 首发标准 `1280×720` 为唯一正式排版基准。没有新增移动端／竖屏专用布局，
也不把未来移动端适配作为当前交付阻断项。

## 玩家界面合同

### 完整展开态

- 左上地图卡显示当前真实地图名和玩家所在格坐标，点击仍进入既有地图页；
- 顶部快捷入口复用既有装备、图鉴和账号按钮及其真实点击逻辑；
- 右上角色卡和战宠卡分别使用当前人物正式头像与当前出战宠的独立大头照；战宠必须由
  `activePetInstanceId` 精确命中且状态为 `battle`，没有真实出战宠时不伪造头像；
- 右侧任务／队伍页签继续接回既有任务、寻路和队伍入口，只展示当前档案与运行时能够
  提供的真实内容；
- 左下消息区复用现有世界消息／聊天控件和真实聊天入口；
- 右下固定栏保留挂机、背包和“更多”；“更多”抽屉承载家族、交易所、邮箱、自动设置
  以及满足现有权限条件时才显示的 GM 入口；
- 所有主要操作都能通过左键和明确按钮完成，右键不成为任何主流程的前置条件；
- 全屏世界菜单、登录／账号／选角覆盖层或战斗状态仍遵守原有显示边界，不允许 HUD 点击
  穿透或压住正式面板。

### 收起与恢复

玩家点击收起后，地图、顶部入口、角色／任务区、聊天区和完整底栏一并隐藏，只保留一个
小型“恢复”按钮。恢复后回到收起前的正常世界 HUD，不要求打开 GM 工具或调试面板。
收起动作只改变表现层，不暂停世界、不改玩家档案，也不更改挂机、任务、队伍或聊天状态。

## 真实数据与不造假边界

本阶段只投影项目中已经存在的系统和运行时状态：

- 人物名称、等级、生命、经验和头像来自当前真实角色档案；
- 出战宠名称、等级、生命、形态和大头照来自当前真实宠物实例与正式宠物头像目录；
- 地图、坐标、任务、队伍、最新聊天、邮箱状态、登录状态和战斗锁定来自当前运行时；
- 原有 `16` 个功能按钮被重新编排，但按钮事件、面板入口和权威写入路径不被 HUD 替代。

为了追随参考图而伪造尚不存在的活动、VIP／特权、货币、福利、排行榜、邮件数量或未读
红点是明确禁止的。无真实来源的状态宁可不显示；玩家界面也不出现版本号、PC／移动端
标记、raw code、资源路径、QA、录屏、性能或 agent 文案。

## 结构与热路径边界

本阶段新增的聚焦组件为：

- `WorldHudAwakenedPresenter`：把当前角色和有界运行时切片投影为 HUD 显示状态；
- `WorldHudAwakenedView`：复用既有按钮和面板节点，负责 1280×720 锚点、收起／恢复、
  更多抽屉、真实头像和可见性合同；
- `WorldHudAwakenedVisualSkin`：统一暗木、暖金、中文字体、图标和按钮状态；
- `WorldHudOwnerReviewCapture` 与 `record_world_hud_owner_review.py`：在真实
  `Main.tscn` 中以隔离档案执行跨帧左键操作并录制 1× 验收片。

Presenter 不拥有业务状态，不保存档案，也不发起网络请求。主循环只使用角色、当前战宠、
队伍 ID、最新消息 ID、邮箱按钮状态、认证和战斗状态等原始轻量字段构成变更签名；签名
未变化时不重建 HUD 投影。禁止在 `_process`、`_draw`、HUD 签名或逐帧刷新中调用完整
`PlayerProgressModel.normalize_profile`、扫描全背包／全宠物／全任务、执行文件 I/O 或
发起网络请求。角色和宠物头像路径只在状态变化时解析，视图不逐帧加载纹理。

## 原创图标资产

正式运行包位于：

```text
client/godot/assets/ui/world_hud_awakened_v1/
```

包内有 `14` 张 `128×128 RGBA8` 运行时图标及其 `14` 张 `1254×1254 RGB8` 绿色色键
生成源，覆盖账号、自动设置、背包、聊天、收起、装备、家族、挂机、邮箱、地图、交易所、
更多、队伍和任务。源图均为本项目通过 OpenAI ImageGen 原创生成，运行图由色键去除、
透明边界整理、居中和高质量缩放派生；未使用任何外部游戏资产。

完整尺寸、字节数、SHA-256、职责、授权状态、派生关系和替换路径记录在：

- `client/godot/assets/ui/world_hud_awakened_v1/asset-manifest.json`；
- `client/godot/assets/ui/world_hud_awakened_v1/source-and-ownership.md`；
- `client/godot/assets/ui/world_hud_awakened_v1/generation-prompts.md`。

`runtimeEnabled=true` 只表示运行时可以加载，并不等于项目所有者已接受最终画面。任何
替换必须先更新同名 source，再重新派生同名 runtime PNG，并同步更新 manifest；不能只
覆盖运行图而遗失来源链。

卡片与跨帧世界移动，因此上方旧 Phase 382 视频继续作为完整 HUD 流程证据，不再作为任务
卡精确最终像素的唯一证据。

## 性能证据

世界 HUD 属于持续显示的高频界面，最终验收必须同时记录改造前后空闲探针、真实跨帧
移动探针及相关面板压力检查。最终结果：

```text
空闲探针（固定 60 FPS、1200 帧）：`process_total=0.04ms`、
`hud_signature=0.01ms`、`hud_update=0.01ms`、`draw_world=0.05ms`；
真实跨帧移动探针（固定 60 FPS、1800 帧）：`process_total=0.04–0.05ms`、
`hud_signature=0.01ms`、`hud_update=0.01ms`、`draw_world=0.04–0.05ms`，
移动检查 `status=ok`、路径长度 `11`、起点 `(720,630)`、终点约
`(982.43,644.58)`。世界 HUD 相关定向回归 `9/9` 通过；Presenter、View、Godot parse、
录像工具 `4/4` 单测、44.7 秒 H.264/AAC 全流解码均通过。
```

性能结论只覆盖已执行的 CPU 热路径、真实输入和面板检查；不得把单机 HUD 探针冒充
GPU 完整分析、移动端发布证明或 200 人同图容量证明。

## 非目标

- 不复制参考产品的像素、UI 贴图、角色、图标、商标、活动排期或数值；
- 不新增虚构活动、福利、VIP／特权、货币、红点、未读数量或社交状态；
- 不改变任务、队伍、聊天、背包、宠物、角色、邮箱、交易所或 GM 权限的业务规则；
- 不借 HUD 重排新增客户端权威写入、全档案上传或逐帧网络请求；
- 不在本阶段制作移动端、竖屏或触屏专用布局；
- 不把工程验收、自动录屏或性能数据展示在正常玩家界面。
