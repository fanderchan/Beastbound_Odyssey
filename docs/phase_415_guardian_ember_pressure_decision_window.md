# Phase 415：焰心守护兽焰压命中预算决策窗

## 当前结论

本阶段已完成 P1.5 第三类高端 Boss 决策机制的工程候选：只有服务端权威登记的
`ember_core_guardian_group` 会在焰心守护兽首次降到 60% 生命时开启一次焰压环。下一回合内，玩家需要
控制由当前可操作角色数推导出的主动命中预算；命中但不超限会令 Boss 破甲一个完整决策回合，超限则令
Boss 攻击强化一个完整决策回合，完全不命中则中性结束。

服务端权威、客户端回放、真实 Main 画面与性能证据均已通过；项目所有者尚未明确接受 V10 精确画面，
所以本阶段仍是 `owner_review_pending`，不勾选 P1.5c，也不把候选机制带入正式运行。工程候选可以安全地
提交和推送：目录要求每个机制显式声明 `runtimeEnabled`，当前焰压固定为 `false`；普通服务加载器不会
初始化、恢复或结算待审机制，只有测试依赖注入可以显式读取候选规则。

待审赤角兽外观也已从正式地图遭遇中移除。地图只保留服务端基础形态、名称、不可捕捉边界和待启用机制
ID；V10 所需的外观、显示名与比例集中在机制目录的 `qaPresentation`，且校验器只允许它存在于关闭的机制。
因此本提交不会让普通玩家看到未发布 exact-form 的占位回退，也不会提前触发焰压。

旧 V6～V9 均已作废，不得作为验收证据：V6 的 QA 预览硬编码了尚未发布的赤角兽外观并把 10 人阵容上限
写死为 `1`；V7 改成从地图和机制目录读取真实外观、身份与上限 `5`，但随后“直接命中”文案与装备主动
群攻的权威计数仍不一致；V8／V9 虽补齐规则，却分别出现中文词组拆行与行末孤字。V10 同时修正这些失真，
录像预览只从权威地图／机制合同构造画面，提示固定为三行短句。

## 参考意图与原创边界

StoneAge 8.0 只作为成熟回合制游戏“规则先可读、玩家决定改变结果”的行为参考。本机制没有复制参考项目
的源码、数值、美术或 Boss 规则。Beastbound 的原创取舍是把“集火”变成一次可见的命中预算：少量准确
输出换取弱防窗口，贪多则触发高攻惩罚；它与地脉守护兽的防御／换宠／控制、潮回守护兽的转火护卫形成
第三种不同决策，不新增隐藏层数、额外货币或每回合重复计数。

## 服务端权威合同

| 项目 | 固定行为 |
| --- | --- |
| 启用来源 | 权威遭遇同时给出 `ember_core_guardian_group` 与 `guardian_ember_pressure_v1`，并且机制目录 `runtimeEnabled=true`；当前候选为 `false` |
| Boss 槽位 | 固定 `enemy.front.3`；生命首次降到 `60%` 以下才触发 |
| 合法命中者 | 开启瞬间仍在场、带权威账号归属的玩家或宠物 actor；敌方、召唤占位和无账号单位不计数 |
| 安全上限 | 开启瞬间冻结为 `ceil(合法命中者数量 / 2)`，最少为 `1`；客户端不能提交或改写 |
| 计数范围 | 对 Boss 造成正伤害且未闪避的普通攻击／宠物技能各计一次；装备主动群攻命中 Boss 时按施放者计一次；合击按合法参与者去重计数；反击与持续伤害不计 |
| 零命中 | 焰压自行熄灭，不改 Boss 攻防，机制完成 |
| 安全命中 | `1..上限` 次令 Boss 防御按基础值 `70%` 向下取整，保持一个完整决策回合 |
| 超限命中 | 超过上限令 Boss 攻击按基础值 `130%` 向上取整，保持一个完整决策回合 |
| 恢复 | 结果回合结束后恢复权威基础攻防并永久完成本次机制 |
| 异常收口 | Boss 死亡／离场或开启时没有合法玩家 actor 会完成机制并清空意图 |
| 重连安全 | phase、合法 actor 集、基础攻防和开启回合由严格 schema 恢复；伪造上限会被重新推导 |
| 公开状态 | 只投影机制、Boss actor、回合、安全上限、标记样式和中文提示，不投影账号 ID 或用户名 |

机制目录继续使用 schema 2，并按 `targeted_charge`／`tide_core`／`ember_pressure` 分型严格校验。每项都
必须显式声明布尔型 `runtimeEnabled`；默认服务端只运行开启项，QA 规则只能通过测试依赖注入显式允许。
地图只声明机制 ID；客户端不能提交阈值、命中名单、上限、倍率、持续时间或结算结果。

发布证明并通过关闭态／开启态导出门，移除 QA 候选字段并显式开启机制，不能把 QA 预览冒充正式发布。
