# Phase 472：首批融合原子发布门禁与导出合同

## 结果

本阶段把 P1.4 从“关闭态素材和发布证明模型均已准备”推进到“具备可审计、可回滚的唯一正式开放路径”。
新增 `tools/promote_pet_fusion_runtime_release.py`，默认只读检查；只有项目所有者明确接受当前候选、批准
输入与仓库证据逐文件哈希一致、两只专用画像决定的精确 SHA-256 已进入可信白名单、关闭态基线完整，
并且权威服务端接受整份候选证明时，才允许原子写入。

本阶段没有替项目所有者批准苔垒角兽 V4E 画像，也没有生成真实 owner decision、运行发布证明或打开
正常玩家入口。当前生产事实继续是：

```text
releaseApproved=false
runtimeEnabled=false
playerEntryOpened=false
portraitReleaseGate=false
```

## 修复的真实发布阻断

原画像 owner decision 计划写入每只宠物的 `qa/portrait/owner-decision.json`，但该目录已有
`.gdignore`。这会造成编辑器源码树能读取决定、PC 导出包却不包含决定，客户端发布证明在正式导出后必然
失败关闭。

现在两只融合宠统一使用：

```text
portrait/owner-decision.json
```

发布工具同时检查 macOS 与 Windows Desktop 预设必须是 `all_resources` 且没有排除过滤，并拒绝任何位于
`.gdignore` 下的画像决定路径。客户端在导出包内完整读取并哈希运行画像、画像元数据与 owner decision；
master、资格蒙版、ownership 正文等源档只要求安全路径、SHA-256 形状及相互引用一致，由权威服务端在
仓库侧逐文件复验。这样既不把源档误当运行资源，也不降低服务端证据强度。

## 原子开放顺序

发布工具的唯一写入顺序是：

1. 写入两只专用画像 owner decision、总 owner decision 和运行发布证明；
2. 写入 ownership、画像元数据、两只宠物动作整包元数据；
3. 更新宠物美术目录；
4. 最后才把生产融合目录 `runtimeEnabled` 改为 `true`，作为玩家入口的提交点。

任何普通异常都会按反向顺序恢复原字节；因此回滚时先关闭融合目录，再恢复其余依赖。工具会在写前
锁定批准输入和全部待写文件的原字节，拒绝并发漂移；临时文件采用同目录写入、`fsync` 和原子替换，
不会把半份 JSON 暴露给读取方。提交点前即使进程中断，玩家入口仍为关闭；提交点后所有依赖已经安装，
且候选在写前已经通过权威服务端模型。

## 生命周期与朝向一致性

正式候选不再只修改顶层运行开关。发布器会同步把身份、关键姿势、12 个战斗动作、真八向世界动作、
世界整包和战斗整包提升为 `approved`，并把生产范围改为
`formal_nonrideable_runtime_release`，清除“仅供隔离 owner review、不得发布”的旧说明。首版两只成品仍
明确 `rideableTarget=false` 且 `riding=null`。

客户端和服务端同时锁定敌方 `front_3quarter_sw + flipH=true + southeast`、我方
`back_3quarter_ne + flipH=true + northwest`，并要求动作元数据顶层与 `battleVisual` 两处映射完全一致。
新增负向回归证明，任何一侧朝向被改错都会使发布证明失效，而不是等玩家在战斗画面中发现。

## 明确授权输入

`--apply` 同时要求：

- 仓库内不可变批准输入 JSON；
- 命令行提供该文件的精确小写 SHA-256；
- 显式 `--owner-accepted-current-candidate`；
- 批准输入精确绑定 Main 实机验收、阶段记录、画像证据，以及关闭重放、三宠权威事务、幂等／断线／
  冲突／回滚、真实 Main 入口与性能四类发布证据；
- 两只画像决定的候选 SHA-256 已由代码审查固定在画像审计可信表。

工具不会制作验收片、伪造证据或从聊天上下文猜测批准。缺少任一项时，默认检查返回 `blocked`，并保持
生产关闭。

## 后续与非目标

- 项目所有者明确接受或拒绝当前苔垒角兽 V4E 画像及本次首批不可骑融合运行范围后，才生成真实批准
  输入和最终 Main 证据；批准前不修改可信摘要表。
- 真正开放时必须由本工具完成一次原子事务，随后复验客户端、服务端、正常 Main 入口和 idle／移动性能，
  再提交并推送开放结果。
- 本阶段不修改融合概率、成长、技能遗传、绑定、交易、消耗、三宠权威事务或像素素材，也不把发布诊断
  暴露在玩家 UI。
