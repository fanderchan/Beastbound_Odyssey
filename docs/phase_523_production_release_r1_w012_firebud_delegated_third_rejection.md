## 第三次退回依据

### 1. 全图主体安全求解把村庄压成了角色展板

W009 为避免 HUD 遮挡，把玩家、全图 14 名 NPC 和 7 个关键环境物件一起送入镜头求解，并把 `14/14` NPC 同屏设为正式门禁。W011 真实 Main 确认它确实没有裁边或 HUD 交叠，但代价是镜头主动把全图服务角色拉进同一画幅：角色围成规则阵列，村口更像功能验收展台而不是玩家正在行走的村庄。

正确边界应是“当前自然进入画面的主体完整且避开固定 HUD”，而不是“镜头把全图主体都拉进来”。安全构图必须局部化到基础玩家镜头附近，并对可见主体做完整 alpha 门禁；不得通过隐藏 HUD、缩小人物或删除服务解决。

### 2. 首屏密度和空间层级仍不自然

村口首屏同时出现大量静止 NPC、记录柱、摊位、花箱和任务标记，人物脚点虽然达到自动间距，视觉上仍是围绕空白中心等距站立。训练场则是大面积绿底、十字道路和互不关联的训练散件，缺少围合、入口、训练区层级以及能够建立方位记忆的大地标。

后续必须把“角色数量完整”与“同屏角色数量”分开：保留 14 名 NPC、服务合同、碰撞和可达性，但只让玩家当前位置附近的服务簇进入自然画面；随后用已批准或新生产的 Firebud 物件建立前景、背景、功能簇和路线终点。

### 3. 角色、地表和环境物件仍像三套素材并置

真实 1280×720 画面中，玩家与 NPC 的像素密度、边缘锐度、对比度和体量不一致；高细节环境物件又明显强于平坦地表。当前 `colorModulate` 与 display size 的数值一致性只能证明实现稳定，不能证明整幅画面已经形成统一的明暗、清晰度和比例语言。

该问题必须在局部安全构图和空间层级稳定后单独收口，不能再用一轮全局缩放／调暗参数冒充完成。
