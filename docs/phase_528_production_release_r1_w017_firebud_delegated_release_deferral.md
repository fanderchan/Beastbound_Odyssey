# Phase 528：生产发布 R1.W017 Firebud v2 委托审片建议首发延期

日期：2026-08-26

## 目标与结论

本阶段只关闭 `R1.W017 OWNER｜Firebud v2 第三次返工后发布决定` 的“批准／退回／延期”决策，不修改地图、NPC、HUD、运行时代码、bundle 生命周期或玩家数据。

项目所有者此前明确说明：

> 我不会验证。你自行验证。。不停推进。。

这项指令把审片判断交给 Codex，但不等于项目所有者亲自接受精确像素，也不授权伪造 owner acceptance。Codex 以受委托美术总监身份审看 W016 当前材料后，作出以下建议：

> Firebud v2 第三次返工已达到当前内部冻结线，不再新增无证据返工；由于项目所有者未签署接受且全游戏正式美术仍未完成，建议首发延期。冻结候选并保持普通玩家不可达，旧正式版本继续有效。

这不是项目所有者批准，不创建 `ownerAcceptance`、`releaseAttestation`，也不允许 R1.02 执行 promotion。它只为 R1.02 提供“延期”分支，让研发离开无止境的 Firebud 局部打磨，继续处理发布路线中其他候选和更大的正式内容缺口。

## 为什么不再退回 Firebud

### 1. W012 的“角色展板”问题已关闭

当前镜头不再为了 `14/14` NPC 同屏而主动拉远。村口画面围绕玩家所在生活服务簇展开，其他 NPC 会自然进入或离开边缘；人物保持可读体量，任务 HUD 仍固定完整。局部镜头比 W011 更像正在行走的村庄，不再像全角色功能展台。

正式取证又补上地图端点夹紧场景：镜头只在可达锚点区间求解，并把人物完整 alpha 设为硬优先。训练 `[18,17]`、十动作和完整视频均证明人物不再钻入顶部／任务／底部 HUD。

### 2. 村口服务和训练场空间层级已形成

村口入口民生、宠物照料、高阶成长三簇之间已有道路和留白，记录图腾不再挤在 HUD 边缘。训练场不再只是十字路加散件：围栏、靶架、蜂蜜岩、路线目标和返回村口亭形成可辨认的训练段落与路线终点。局部画面仍允许草地留白，这是训练场功能密度差异，不应再用堆满物件解决。

### 3. 人物、地表、物件的视觉权重已进入同一幅画面

人物与 NPC 的高度和比例处于冻结区间，地表保持低对比底板，训练物件承担中景地标；没有 W011 那种角色、平地、高细节物件三套素材互相争夺焦点的明显断层。道路／草边的大尺度不规则过渡也比早期矩形拼块自然。

当前仍能看到整个游戏的正式 UI、其他地图、宠物和动画尚未全部达到商业首发线，但这些是 P2.2/P2.3/P2.5 的全局缺口，不是继续退回 Firebud 两图就能解决的问题。没有新复现缺陷时，不新增 W018。

## 为什么不能批准，只能建议延期

自动检查和受委托审美判断可以证明当前候选值得冻结，不能替代项目所有者的可追溯接受。现在仍精确缺少：

- `owner_acceptance`；
- `release_attestation`；
- `lifecycle_released_and_enabled`。

同时，生产发布计划中的完整正式美术、音频、其他 owner 候选、支付、运维、签名制品和封测门禁仍大量未完成。即使 Firebud 两图已到内部冻结线，也没有理由让一个未签署候选提前进入普通玩家运行时。因此本轮选择“建议首发延期”，不是“技术 PASS 等同批准”。

## 生命周期与验证边界

本阶段不改 bundle 字节。只读确认仍为：

- `status=owner_review_pending`；
- `ownerReviewStatus=pending`；
- `releaseApproved=false`；
- `runtimeEnabled=false`；
- `ownerAcceptance=null`；
- `releaseAttestation=null`。

bundle SHA-256 与 W016 完全相同，manifest 的活动／superseded 证据引用未变化。W016 已覆盖 runtime、输入、碰撞、性能、HUD 与离线审计；本阶段只验证 Markdown、计划结构、精确哈希和只读生命周期，不重复执行无关完整 CI。
