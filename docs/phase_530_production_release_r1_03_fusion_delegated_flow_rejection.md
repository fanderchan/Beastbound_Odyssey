# Phase 530：生产发布 R1.03 融合肖像接受、结果流程退回

日期：2026-08-26

## 目标与决定

本阶段关闭 `R1.03 OWNER｜融合肖像与融合流程人眼验收` 的本轮委托审查，只做审片、代码事实核对和返工拆分，不修改宠物画像、融合规则、成长、概率、经济、服务器事务或生产开关。

项目所有者已明确把持续验证交给 Codex，但没有亲自签署当前两张画像，也没有授权生成 owner approval。Codex 以受委托宠物美术总监和产品审查者身份作出以下决定：

1. **接受两张画像作为继续冻结的内部候选**：曜冠角兽和苔垒角兽 V4E 的专用头肩像、同血系身份、攻防气质区分和 48／64／96／128px 可读性没有新的视觉阻断，不重做画像；
2. **接受首批不可骑边界**：两只融合目标作为终局宠只交付 standalone pet，不生产或暗示骑乘组合；
3. **退回当前融合流程候选**：Phase 445/479 权威 Main 证据只展示关闭态、两条路线报价和第一次不可逆确认，没有展示成功结果页、失败结果态或失败后的可恢复操作；当前运行实现成功／失败也只把一行状态消息重新塞回材料选择页，不能持续展示服务器确认的成品身份和消耗结果。

因此本轮不批准融合运行开放，不创建画像 owner decision、总 owner approval input 或 release attestation，不执行 promoter。返工拆为 R1.W018–R1.W020；当前游标转到 R1.W018。

## 精确退回根因

### 1. 证据没有覆盖 R1.03 自己要求的结果与失败态

Phase 445 片的六个章节精确为：

```text
closed_open
solar_preview
solar_armed
moss_preview
moss_armed
closed_final
```

报告同时记录 `actualLeftClicks=2`、`secondConfirmationExecuted=false`、`networkRequestCount=0`。这对“生产关闭且不会误消耗”是可信证据，却没有成功结果、失败提示、服务端权威成品卡或失败后的重试／重新报价状态。

R1.03 明确要求展示“来源/结果肖像、融合确认、结果页、正常状态、失败状态与当前不含骑乘的边界”。当前材料只覆盖前半段，不能用自动检查或一行日志补齐人眼证据。

### 2. 当前产品表面没有持久的权威结果态

当前成功路径在应用服务端档案后清空 quote、重置确认，并把服务端 message 写入 `_pet_fusion_status_message`；失败路径也只映射一条玩家文案后刷新原材料页。面板没有一个独立 outcome view 保存：

- 新成品画像、名称、Lv1／一转和终局身份；
- 实际继承的特殊主动和唯一被动；
- 绑定／交易结果；
- 三只材料是否已消耗；
- 失败时明确“本次没有消耗宠物”以及下一步操作。

对一次会永久消耗三只一转宠的操作，状态横条不足以承担最终回执。玩家如果在成功刷新后看到空材料槽，只能凭短消息判断交易是否完成；失败后也不清楚应重试、重新报价还是重新选材。

### 3. StoneAge 8.0 参考与 Beastbound 原创取舍

本地 StoneAge 8.0 参考的成熟基本链路是“选择三宠 → 服务端执行 → 失败立即提示／成功刷新宠物结果”；它至少不会让操作结束点没有反馈。Beastbound 不复制其窗口、数值或美术，但应保留“事务结束必须有明确结果”的行为意图。

Beastbound 的三宠融合比参考实现多出服务端报价、双确认、技能遗传和终局约束，因此增加一张简洁的权威结果卡有明确收益：让玩家核对成品和实际继承，让失败恢复可操作，并降低高价值消耗争议。这不是为了堆功能，而是关闭当前证据和产品共同暴露的终点缺口。

## 返工任务

### R1.W018 AUTO｜融合权威成功／失败结果态

在 focused model/view 中增加成功和失败 outcome，不把新领域塞进 `main.gd`：

- 成功只消费经过严格解析且已经应用服务器 profile/revision 的结果；
- 显示正式结果画像、名称、`一转 Lv1`、实际继承主动／被动、绑定／交易、终局和不可骑；
- 明确“三只材料已消耗”，提供返回宠物栏的左键按钮；
- 失败使用既有玩家错误映射，不显示 raw code；明确“本次没有消耗宠物”，按错误类型提供重新报价或重新选择；
- pending／成功／失败均不能重复提交，陈旧 quote 和 revision 冲突继续失败关闭；
- 补模型、面板、客户端领域和 1280×720 定向检查。

### R1.W019 AUTO｜融合当前 Main 精确证据重冻

在隔离 QA lane、无真实账号写入、无生产目录开放的前提下，从真实 `Main.tscn` 记录两路线来源／结果画像、报价、双确认、成功结果、失败恢复、关闭态和不可骑边界；验证视频完整解码、真实左键、布局、玩家文案、零 raw ID、零真实网络／档案副作用和性能。

### R1.W020 OWNER｜融合返工后委托复验

只审 R1.W019 当前精确画面。若结果态清晰且无新根因，给出冻结／延期建议；没有项目所有者亲自签署时仍不生成 owner acceptance、可信画像 digest 或 release attestation。
