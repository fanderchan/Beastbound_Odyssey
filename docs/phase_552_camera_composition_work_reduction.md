# Phase 552：减少不改变镜头结果的构图计算

日期：2026-09-18。承接 Phase 551 的二层移动诊断，只优化已有相机求解器；R1.W024、P2.1a 和候选美术接受继续待完成。

## 问题与修改

`WorldCameraSafeAreaModel.composition_anchor_avoiding_rects_in_range` 原本会先建立候选坐标网格，再对当前位置和所有候选评分。即使人物、地标全部完整可见、没有 HUD 遮挡，也会搜索一个无法胜过当前位置的网格；当前位置还会在网格内被重复评分。

现在先计算当前位置的既有九维评分。只有前七项遮挡/裁切惩罚全部为零、可见主体数已达到输入主体总数时，才直接返回当前位置：此时前八项已经达到理论最优，第九项位移为零，不存在更优解。其他情况保持原候选顺序、边界、优先级和比较容差，跳过已经评分的当前位置。

没有改变缩放、角色/地标尺寸、相机边界、HUD 占用、地图数据、交互或移动规则，也没有新增缓存或逐帧扫描。无效/零尺寸主体和缺少有效视口等不满足完整可见条件的输入继续走原搜索。新增回归覆盖“无 HUD 遮挡但被视口裁切”：仍必须从 `(640, 360)` 移至 `(662, 360)`，防止把无重叠误判为无需构图。

## 正确性与诊断

以提交 `408e3928a9a818f486edcf9c116acbca448ac2c0` 的模型为旧算法。原文件 SHA-256 为 `aeef2c210fa77030a759c74300e510f7f003d3c310d689ddc7af03af9214e6a4`。本机忽略目录中的诊断副本只移除全局类名，并按用途加入调用记录或评分计数；它们不是正式录片入口。

- 在隔离 headless Main 二层移动中记录 64 组不同的真实构图输入；60 次跨帧左键、120 个输入事件全部接收，投影不匹配为零，最终移动目标一致。
- 64 组实际输入和种子 552 的 1000 组随机边界输入，新旧算法输出逐例完全一致。评分调用由 530 次降至 434 次，减少 18.1%。
- 每个实际输入交替运行新旧模型、各重复 40 次，共五轮。旧算法用时为 `64597/64831/64908/64971/64881 μs`，新算法为 `55328/55494/55590/55673/55785 μs`；中位数 `64881 → 55590 μs`，约减少 14.3%。这是隔离算法诊断，不能换算成游戏 FPS。
- 最初整批先旧后新的计时受明显调度波动影响，原始结果保留，未作为性能结论。首次临时跟踪脚本因缩进错误不能解析，该受控进程终止并清理后，仅修正诊断脚本缩进再重测；不是正式游戏脚本解析失败。
