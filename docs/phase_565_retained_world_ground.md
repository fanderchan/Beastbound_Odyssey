# Phase 565：移动反馈复用静态地面绘制

日期：2026-09-19。继续 R1.W024 的运行性能收口。此次减少动态世界重绘时的重复提交，四层画面保持原样；尚未解决或宣称通过正式原生静止增量门槛。

## 原因与实现

原先 Main 同时绘制背景、整张地面和路径等动态反馈。路径或其他世界签名变化时，整组地面绘制命令随 Main 一起清除、重建。以二层当前候选为例，每次重新提交外围地面 2688、基础地面 672、覆盖地面 267，共 3627 条纹理命令。

新增 `world/world_ground_layer.gd`，让背景和静态地面保留在独立 CanvasItem 中。它仍调用原 `MapVisualRenderer.draw_ground`，不改变命令、顺序、坐标、纹理、透明度或过滤方式。图层位于 Main 动态反馈下方，人物和地图物件继续由既有深度层排序；地面贴花及路径反馈留在原位置。

地图修订变化时重新配置缓存，窗口布局变化时更新背景范围。Main 的路径、任务或在线人物重绘不再重新提交地面；同一修订的强制世界同步也不会丢弃缓存。战斗和全屏地图沿用现有世界显隐规则，离开候选后清空活动状态并保留原网格回退。节点没有逐帧处理函数。

这是既有表现的实现优化，沿用 Phase 555 的地图、碰撞和遮挡规则。没有更换像素、缩放、相机、地图权威数据、玩家交互或美术开放状态；不新增玩法或修改 StoneAge 参考行为。

新的图层及其 QA 文件同时纳入地图运行指纹。负向用例先证明遗漏时修改这两个文件不会使旧身份失效，补齐后两项修改均改变身份；相关证据工具 `53/53`。当前运行指纹为 `beastbound-map-runtime-surface-v2:9150c7d3ec3d5f8f0ce120cc8567404b28ab1cd0cd5e5e4d83d15c2522f46c62`，没有把旧回执改写成当前版本。

## 性能

二层同一 Main、180 帧预热、480 帧测量；静止与移动各三轮，前后顺序交替。每个移动场景发送 60 次跨帧左键、120 个真实输入事件，全部接纳，投影不匹配为 0，最终格一致。数据完整保存在 `.run/phase565-performance-final.json`，不挑选最低耗时的单次结果。

下表为三次运行均值的中位数，单位 ms/帧。`draw_world` 按全部 480 帧计算，未重绘的帧计 0。

| 场景与区段 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 静止 process_scope | 0.040625 | 0.040875 |
| 静止 Main process_total | 0.028125 | 0.028250 |
| 移动 process_scope | 0.074000 | 0.084250 |
| 移动 Main process_total | 0.046375 | 0.053125 |
| 移动 draw_world | 0.035625 | 0.001000 |

静止主循环近似原水平，移动场景的世界绘制脚本区段约减少 97%。最终三轮的移动完整处理区段中位数增加 `0.01025ms`，每轮前后差方向并不一致；过往样本不覆盖这次最终结果，因此不据此宣称整体处理耗时或 FPS 改善。每次移动样本中 Main 均重绘 18 次；修改后静态图层在测量期间重建 0 次，实际避免重复提交 `18 × 3627 = 65286` 条地面命令。这是保留了绘制缓存，不是把同一份逐帧工作移到未计时的方法中。初次地图绘制仍有原有成本；不把局部比例宣称为游戏 FPS 提升。

补充原生录制模式移动对照位于 `native-moving-before/`、`native-moving-final/`：两次真实跨帧输入均通过，18 次 Main 重绘及最终格相同；旁观仪表的绘制调用、物件数、图元数逐帧一致，图形工作量没有扩大，汇总为 `native-parity-final.json`。录制模式的 `TIME_PROCESS` 均值为 `3.197→4.904ms`；该仪表含起始过渡帧、窗口不在前台，因此本轮只确认绘制工作量相同，不能宣称总帧耗时改善或替代正式 48 组矩阵。headless 固定步长同样只是脚本诊断。

前期另作地面移除的反事实诊断：减少渲染物件并未稳定降低脚本耗时，因此没有把静止增量根因归给地面，也没有据此实施裁剪、删图或放宽门槛。相关原始记录保留在同一诊断目录。
