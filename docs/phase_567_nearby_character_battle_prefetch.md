## 原因与实现

战斗投影修复后，四套人物终于正确显示，但原预取只读取本人外观。真实首次切战仍需同步加载其他三套人物，完整准备为 `430.989ms`，其中人物为 `424.329ms`。

预取计划现在还读取当前地图的公开在线名单，由在线缓存更新事件触发。本人优先，其余外观去重并排序；位置或名单顺序变化不改变计划，不清空队列，也不重复枚举纹理。其他地图、损坏位置和重复外观不扩大计划。仍使用人物目录解析 ID，不读取远端私有档案，不从网络获取图片，不遍历全游戏图鉴。

同时最多四套人物、六个已有遭遇宠物形态；资源硬上限由 1536 调到 2048，容纳当前场景实际需要的 1620 张图。每帧最多八次操作、四个在途请求、1500μs 脚本预算继续保留。完成前不阻塞取纹理，离开场景或外观离开后释放预取器的无用引用；既有 headless 同步回退和美术开放检查不变。新增预取将最多三套人物、540 张当前动作纹理的驻留时间提前，不能把加载等待改善说成零内存成本。

`main.gd` 只转交现有公开缓存，`PanelFlowCoordinator` 只加事件接线；选择、签名和加载仍在既有 battle 预取模块。没有新增逐帧名册扫描、轮询请求、存储写入或兼容协议字段。未修改任何资源像素、比例和 owner / runtime / release 开关。
