# Phase 572：缓存人物动画片段并延后镜头备用求解

日期：2026-09-19。承接 Phase 571 的性能调查，继续 R1.W024。本阶段减少人物世界动画和镜头构图的重复计算；没有修改人物尺寸、动作时机、原始图片、地图拓扑、HUD 或权威玩法。

## 实现

`Player` 原先在每个 process 帧查询动画元数据，在移动的 physics 帧重复解析当前帧路径。现在按当前人物形象缓存朝向／动作的帧率和纹理引用，时间推进和选帧仍发生在原来的调用位置。相同朝向直接选择缓存帧；往返转向复用已准备的片段；换人物形象时释放上一形象的片段缓存。当前目录每个形象最多 16 个片段、40 个已有纹理引用，不复制图片，也不缓存所有人物形象。

Main 仍先按既定优先级为人物和地标构图；只有结果与 HUD 遮挡区相交，才计算原有的人物专用备用位置。原先即使不需要备用位置也会求解一次。求解器、参数、完整 alpha 轮廓和最终回退条件保持一致。

这是已有行为的计算优化，不引入新的 StoneAge 玩法差异。远端人物复用 Player，可使用同一优化，但本轮没有做 200 人容量测试。

## 正确性与局部测量

人物运行检查新增四套形象 × 八方向 × 站立／行走，共 64 个片段的验证：覆盖两轮动画的帧边界前后、负时间、长时间、重复朝向调用，以及不同 process 间隔和 2.5 倍移动速度。继续保留原骑乘兼容与降级检查。

另将修改前 Player 与正式修改后 Player 并排执行 2400 步混合序列，跨形象、朝向、动作、速度切换，逐步比较纹理、动画时间和显示节拍，差异为零。以下为五轮交替顺序、每轮一万次更新的耗时中位数，单位 **μs/更新**；仅代表动画局部工作，不是整游戏 CPU 或 FPS 提升。

| 更新方式 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 静止 process | 1.8056 | 0.2482 |
| 行走 process＋重复同朝向 | 10.2753 | 0.9515 |
| 行走 process＋每次转向 | 10.7508 | 1.7909 |

初版只缓存当前片段，极端连续转向从约 10.51 升到 21.60 μs；该结果保留在 `benchmark-first-attempt.json`。最终实现复用当前形象的多个片段，才得到上表结果。

## 整场景前后对照

二层候选使用 12 个独立 headless Main：修改前／后 × 静止／移动 × 三轮，并交替执行版本顺序。每次预热 180 帧、测量 480 帧、每 60 帧报告；六个移动样本均发送 60 次跨帧左键、120 个鼠标事件，全部接收，屏幕投影误差计数为零，最终目标到达正确。没有把同帧辅助函数调用当作移动输入。

下表为三次运行均值的中位数，单位 **ms/帧**。

| 范围 | 修改前静止 | 修改后静止 | 修改前移动 | 修改后移动 |
| --- | ---: | ---: | ---: | ---: |
| 相机区段 | 0.003000 | 0.003000 | 0.018625 | 0.015625 |

完整脚本范围的静止和移动耗时分别下降约 9.1% 和 10.1%。这是固定步长、无原生绘制的局部前后诊断，不代替正常时钟进程 CPU、原生四层矩阵或正式发布验收。
