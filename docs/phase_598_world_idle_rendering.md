# Phase 598：静止镜头休眠与按需绘制

日期：2026-09-21。将 Phase 597 的相机诊断接入正常客户端：世界完全停稳时减少重复画面提交，移动、菜单、战斗、录制或性能测量时恢复相应绘制策略。开发基线为 `0385e63fdbb707f50664ccebbad65a426b70d270`。这完成一个运行优化切片；P2.1a／R1.W024 仍有正式地图性能和精确视觉证据待办。

## 实现与边界

[WorldIdleRenderController](../client/godot/scripts/world/world_idle_render_controller.gd) 观察相机目标、实际中心、缩放、视口及画布变换。镜头稳定三帧且距离目标不超过 `0.01` 世界单位时暂停 Camera2D 的内部更新；变化时恢复。旋转、偏移、physics 回调、拖拽等未覆盖模式继续使用引擎更新。退出 Main 时恢复原有全局渲染设置。

SceneTree、输入和物理更新继续运行，Main 保留原有空闲 30／活动 60 FPS 上限。有效世界点击在输入处理时立即应用活动预算，等待防抖的点击也保持活动状态。普通空闲世界启用按需绘制；性能探针和显式审查捕获即使在启动后才启用，也会动态要求连续绘制。MovieWriter 的固定连续绘制请求在启动时读取。已有 VSync 规则保持各自口径。

这是呈现调度调整，不涉及玩法、数值、网络协议、地图素材或玩家 UI 文案。引擎行为依据和原型来源见 [Phase 597](phase_597_idle_camera_render_diagnosis.md)。新控制器和回归文件已加入地图运行内容指纹；单独修改任一文件都会令旧证据失效。

## 相机、输入与性能回归

最近的 `--auto-camera-check` 扩展包含 **19 项／1050 帧**双视口对照：移动、平滑尾段、缩放、窗口尺寸、传送重置、父级变换、外部画布写入、设置变更唤醒及各项回退。镜头中心和鼠标世界坐标误差均低于 `0.01` 世界单位。真实 Main 另外检查四层 `1.52×`、首次跨帧鼠标移动、菜单、离线战斗返回，以及启动后打开／关闭性能探针和捕获模式。

定向客户端 **5/5**，最终解析 **1/1**；性能套件修改前、修改后均 **5/5**；Python 地图证据构建器 **53/53**。没有运行全量 CI。性能套件覆盖静止、移动、跨帧连点、商店选择与属性面板；它是定向回归，不能代替原生地图性能门。

| 场景 | 修改前中位数 / p95 | 修改后中位数 / p95 |
| --- | --- | --- |

## 同版原生对照

同一进程顺序重建四个真实 Main，固定岩脉二层同一美术，控制器禁用／启用／启用／禁用。各段在明确开始操作和稳定前台准备后测量 12 秒；普通时钟、1280×720、VSync 开启、Dummy 音频，没有固定步长、录片或性能探针。CPU 用 `ps` 累计 CPU 时间差除以单调墙钟差计算。

| 顺序 | 控制器 | 处理帧 / 绘制帧 | 进程 CPU |
| --- | --- | --- | --- |
| 1 | 禁用 | 361 / 361 | 7.747% |
| 2 | 启用 | 361 / 86 | 3.945% |
| 3 | 启用 | 361 / 86 | 3.750% |
| 4 | 禁用 | 361 / 361 | 7.757% |

本次两组按采样时长加权的 CPU 为 **7.75% → 3.85%**，约减少 **50.4%**。四张游戏视口图均为 1280×720，RGBA 像素及文件 SHA-256 一致；人物位置与画布变换一致。结论仅覆盖本机此静止场景，不是整款游戏或 200 人同图容量结论。

移动对照每段发送 30 次鼠标点击，按下和释放分布在不同帧，四段共 **120 次点击／240 个输入事件**。2065 个首个输入送达后的观测帧均绘制，移动中误用节能策略为零；各段行走约 `1204.72` 世界单位。逐帧记录明确区分入队、输入送达与前一帧的绘制计数，不能把输入送达前的静止省略画面算成移动漏绘。四段零失焦／不可绘制，不据移动 CPU 的小样本波动宣称性能提升。

另一个原生 `--perf-probe` 样本完成 **360/360** 帧绘制，相机可休眠而测量仍连续绘制。普通按需渲染的节能样本不导入正式地图矩阵，也不改变其逐帧绘制、前台及性能阈值。

人工联机复验使用真实 Main、四个 HTTP 测试队友和隔离内存后端，以真实鼠标在四层从 `(21,8)` 走到 `(23,6)`，打开／关闭背包，再走到 `(25,7)`。200 次状态采样均保持联机、洞穴美术及 `1.52×`；捕获模式启用后的 **4066/4066** 个完成帧均已绘制，缺帧与后备强制绘制均为零，客户端正常退出。结果位于 [本轮联机检查](../.run/guardian-review/20260920T191409.796833Z/render-continuity.json)。本轮仅复验移动、面板和动态连续绘制，没有重打守护战或走完整返村路线；使用高生命 QA 队伍，不作为正常难度验收。

## 保留的失败与剩余工作

- 最初新加 QA 参数被既有启动源码审计拒绝，未绕过审计；改为扩展现有 `--auto-camera-check`。早期输入夹具遗漏窗口缩放，战斗夹具误切回村庄，两者都修正后重跑。
- 首次原生移动发现一帧尚未恢复活动预算，已修复并增加首个已投递输入帧检查。另一个断言曾在事件入队后立即检查，早于输入实际投递，已按接收计数和实际帧修正。
- 多次原生准备／采样因失焦、不可绘制或窗口操作错误失败，原始失败记录保留。没有降低前台门槛。增加显式开始页、重新连接窗口工具后取得有效样本；这不证明窗口异常的根因已经解决。
- 首次联机人工检查完成了行走与背包操作，但后开启探针未传入渲染策略，连续绘制严格检查发现 **2116** 个缺帧，整轮判失败。修复动态请求并复验，未改录片连续性门槛。

现有正式地图静止增量证据仍为 Phase 579 的 `0.165–0.188ms > 0.100ms` **FAIL**，本阶段没有重跑完整 48 组矩阵或安装正式证据。接下来验证新源码的正式矩阵、精确地图动作／截图配对，再进入受委托复审；素材所有者接受仍待完成。原有 **107** 项候选修改和 **111** 项保护文件完整保留。
