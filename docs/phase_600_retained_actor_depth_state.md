# Phase 600：复用人物排序状态与分项耗时验证

日期：2026-09-21。继续 R1.W024，开发基线 `373321318f4151bd212cacb8ff4a53246a606445`。本轮减少世界人物排序的重复查询和分配；二层原生对照中，排序查询由平均 `22.364µs` 降至 `17.503µs`，约减少 22%。这是一项局部优化，尚未解决全部静止增量，不代表正式性能门通过。

## 实现与行为边界

`WorldDepthLayer` 为注册人物保留带类型的状态记录，直接比较实时脚点深度和可见性，省去每帧两次字典取值、动态数组拆解和待清理数组。记录按 stableId 在注册时排序；移动只更新数值，不再为签名重新复制、排序 ID。倒序检查可安全移除同一帧释放的多个人物。

沿用原有晚序刷新、动态脚点方法／元数据、三位小数签名边界，以及 `depthY / tiePriority / stableId` 排序合同；同名人物重新注册仍强制刷新。没有改变 Phase 555 的遮挡规则、Phase 575 的人物范围查询、人物比例、相机、动画、地图或输入。此为既有行为的技术优化，不新增玩法规则；遮挡查询没有采用基于单一通知的缓存捷径。

## 定位依据

首次分项禁用对照在六个新 Main 中分别保留原逻辑、跳过遮挡查询、暂停深度层回调；画面逐像素一致，但总区段时间波动较大，不能从单个低值推断收益。记录在 `.run/phase600-depth-ablation/`，未作为验收或优化收益。

随后在同一原生窗口依次运行网格／美术／美术／网格。每段预热后记录 1920 帧，使用相同优先级的临时节点分别调用该版本的原排序和遮挡方法，并在调用前后计时。四段共 7680 帧均实际绘制，零失焦、零不可绘制，位置／画布／排序不变；两种场景各自的重复截图完全一致。

| 每个观察帧，两段均值的平均 | 网格 | 美术 |
| --- | ---: | ---: |
| 排序查询 µs | 8.772 | 21.840 |
| 遮挡查询 µs | 0.808 | 20.325 |
| 全部 Node 回调区段 ms | 0.148033 | 0.328846 |

两项查询只解释部分额外耗时，不能把整个增量归因于遮挡或排序。该诊断未启用详细 `perf-probe` 或脚本分析器，但临时计时本身仍有开销；固定步长、运行时 VSync=0、连续绘制也不同于普通静止节能模式。结果见 `.run/phase600-depth-timing-retry/report.json`。此前准备窗口超时、零 Main／零有效样本的失败保存在 `.run/phase600-depth-timing/`，没有覆盖或混入结果。

## 前后验证

既有地图运行、相机、点击寻路和人物外观检查加解析 **5/5**。世界深度回归增加原地修改脚点元数据与同帧释放多个人物；既有动态方法脚点、显隐、同名替换、强制刷新及三位小数边界继续通过。随后把成员排序移到注册入口，再补解析和完整地图运行检查 **2/2**。

修改前版本仅在忽略目录保留旧深度层和替换其 preload 的 Main；其余运行代码相同。12 个独立 headless Main，按修改前／后 × 静止／移动 × 三轮交替，均预热 180 帧、测量 480 帧，八个完整报告窗。六组移动共 **360 次跨帧点击／720 个输入事件**，全部接收，投影错误为零，最终目标一致。

| headless 全部回调区段，三轮均值的中位数 ms | 修改前 | 修改后 |
| --- | ---: | ---: |
| 静止 | 0.030750 | 0.030250 |
| 移动 | 0.061000 | 0.059125 |

原生窗口另以修改前／后／后／前运行二层美术，仍按上述临时同帧计时方法，每段 1920 帧。四段 **7680/7680 帧实际绘制**，零失焦；四张 1280×720 图片跨版本逐像素一致，人物、画布和排序不变。

| 每帧，两段均值的平均 | 修改前 | 修改后 |

排序查询改善在两个前后对中均出现；没有把完整区段的小幅变化全部归因于本次修改，也不据此宣称整进程 CPU、FPS 或 200 人容量改善。原始日志、数组、隔离源码和截图分别在 `.run/phase600-headless-comparison/`、`.run/phase600-native-depth-records/`。
